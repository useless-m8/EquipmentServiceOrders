# Ответы на контрольные вопросы по индивидуальному проекту

**23. Какую задачу решает приложение?**
Позволяет резервировать оборудование на определённый период и предотвращать
конфликты броней. На ПР1 проверяет одну новую бронь относительно одной существующей.

**24. Кто предполагаемый пользователь?**
Студенты, сотрудники организаций и арендаторы техники. Администраторы
в дальнейшем будут управлять каталогом, исправностью и выдачей.

**25. Какие сущности выделены?**
Пользователь, оборудование, бронирование и период. Бронирование связывает
пользователя с устройством и задаёт период использования. У пользователя
и оборудования может быть несколько броней.

**26. Какие функции планируются?**
Каталог, поиск свободной техники, создание, просмотр, изменение и отмена
бронирований, расчёт стоимости, регистрация, вход и администрирование.
В ПР1 реализованы проверки периода и доступности, расчёт цены и статус брони.

**27. Какой сценарий реализован сейчас?**
Проверка и подтверждение бронирования проектора на 2,5 часа. Предыдущая
бронь заканчивается ровно в момент начала новой, поэтому конфликта нет.
Оплата трёх начатых часов составляет 750 руб. Данные демонстрационные,
бронирование не записывается в файл или базу данных.

**28. Какие конструкции Python использованы?**
Переменные, строки, логические значения, сравнения, арифметические операции,
преобразования, `if`, `and`, `not`, функции, `return`, f-строки,
импорт `datetime` и `Decimal`. Проверка тарифа и периода использует
`raise ValueError`; обработка пользовательского ввода появится позже.

**29. Что добавится после изучения ООП и Django?**
Классы сущностей, Django-модели и база данных, страницы каталога и броней,
формы, регистрация, аутентификация, права доступа и административная зона.
Далее - REST API, Docker и CI/CD.

**30. Почему область подходит для веб-приложения?**
Есть несколько связанных сущностей и разные роли пользователей. Нужны
хранение данных, операции создания, просмотра, изменения и удаления,
общий каталог и доступ через браузер. Django позволяет реализовать эти
сценарии, а API - подключить другие клиенты. При переходе к базе данных
нужно учитывать одновременные запросы, чтобы исключить двойное бронирование.
