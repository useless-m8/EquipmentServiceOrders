## Индивидуальный проект

Название: «Сервис бронирования оборудования».
Предметная область: резервирование техники для временного использования.
Предполагаемые пользователи: студенты, сотрудники и арендаторы;
администраторы управляют оборудованием и бронированиями.
Выделены сущности: пользователь, оборудование, бронирование и период.

Репозиторий: https://github.com/useless-m8/EquipmentServiceOrders.
Использован уже созданный репозиторий; повторное создание не требовалось.
Согласование темы с преподавателем подтверждает студент.

В `main.py` реализованы четыре функции: проверка корректности периода,
проверка исправности и доступности оборудования, расчёт стоимости и
определение результата бронирования. Начальный законченный сценарий:
активный пользователь бронирует исправный проектор на 15.10.2026 с 12:00
до 14:30. Предыдущая бронь заканчивается в 12:00, поэтому пересечения нет.
При тарифе 250 руб./час с оплатой каждого начатого часа стоимость равна 750 руб.

Использованы строки, логические значения, операции сравнения, `and`, `not`,
ветвления `if`, функции, форматирование строк и импорт стандартных модулей
`datetime` и `decimal`. Строки преобразуются в даты методом `fromisoformat`,
а тариф и длительность - в `Decimal`. Классы, коллекции и циклы для логики
приложения не потребовались. Тесты вынесены отдельно от учебного сценария.

## Результаты проверки

Создано виртуальное окружение `.venv`, проверен запуск программы. Внешние
зависимости отсутствуют. Подготовлены настройки интерпретатора и отладчика
VS Code; фактическая демонстрация отладки в IDE остаётся студенту.

В стандартном отладчике `pdb` выполнены остановка, пошаговое выполнение и
просмотр значений переменных. На временной копии внесена и диагностирована
ошибка: нестрогие сравнения ошибочно блокируют соседние бронирования.
Рабочий код содержит исправное условие. Протокол: `docs/debug_session.txt`.

Команда `python -m unittest discover -s tests -v`: 7 тестов успешно.
Проверены некорректные периоды, пересечения, соседние брони, неисправная
техника, ограничения тарифа, округление оплаты и активность пользователя.
README заполнен по шаблону; существующий `.gitignore` исключает окружение
и кэш Python. Для сохранения результата предусмотрены commit и отправка
в существующий удалённый репозиторий; факт отправки проверяется по Git.
