# Отладка ПР1

## Выполненная проверка

12.10.2026 программа проверена стандартным отладчиком Python `pdb`.
Полный вывод сохранён в [debug_session.txt](debug_session.txt).
Проверка проведена на временной копии `main.py`, удалённой после запуска;
поэтому пути временного каталога в протоколе больше не существуют.
Рабочая программа содержит исправное условие.

Установлен breakpoint на вычислении `has_overlap` (строка 14).
После остановки просмотрены `start` и `booked_end`: оба равны
`datetime.datetime(2026, 10, 15, 12, 0)`. Командой `n` выполнен шаг;
`has_overlap` оказался `False`, функция вернула `True`, бронь подтверждена.

Во временную копию намеренно внесена ошибка:

```python
has_overlap = start <= booked_end and booked_start <= end
```

При тех же значениях после шага `has_overlap` стал `True`, функция вернула
`False`, и программа отказала в бронировании. Причина: включённая граница
ошибочно считает соприкосновение периодов пересечением. Исправный вариант:

```python
has_overlap = start < booked_end and booked_start < end
```

Проверка через `pdb` подтверждает остановку, пошаговое выполнение, просмотр
переменных и диагностику ошибки. Запуск именно в IDE в этой сессии не
выполнялся; его нужно продемонстрировать преподавателю следующим образом.

## Демонстрация в VS Code

1. Открыть корень репозитория. Установить расширения Python и Python Debugger,
   если они ещё не установлены.
2. Выбрать интерпретатор `.venv/Scripts/python.exe` через
   `Python: Select Interpreter`. Настройки проекта уже подготовлены.
3. В `main.py` поставить breakpoint на строке вычисления `has_overlap`.
4. Нажать F5 и выбрать «ПР1: бронирование оборудования».
5. В панели Variables просмотреть `start`, `end`, `booked_start`, `booked_end`.
6. Нажать F10 и проверить `has_overlap == False`; F5 завершит сценарий.
7. Временно заменить оба `<` на `<=` в условии, повторить запуск и шаг.
   Значение `has_overlap == True` объясняет ошибочный отказ.
8. Вернуть оба строгих сравнения `<`, повторить запуск и тесты.
