# EquipmentServiceOrders
## Сервис бронирования оборудования

### Целевая аудитория

- Студенты: для бронирования техники на занятия и проекты.
- Сотрудники: для резервирования оборудования на работу и мероприятия.
- Администраторы: для управления техникой и контроля бронирований.

### Описание предметной области

Сервис предназначен для бронирования оборудования на определённый период.
Пользователь выбирает технику и время использования. Одно устройство можно
бронировать несколько раз, если периоды не пересекаются. Оборудование должно
быть исправно, а пользователь — активен.

### Основные сущности

- Пользователь (User)
- Оборудование (Equipment)
- Бронирование (Booking)
- Период (Period)

### Основные функции

- Проверка периода: время окончания должно быть позже времени начала.
- Проверка доступности: учёт исправности оборудования и пересечения бронирований.
- Расчёт стоимости: оплата каждого начатого часа по тарифу оборудования.
- Подтверждение бронирования: проверка активности пользователя и доступности техники.

На этапе ПР1 реализован консольный пример с одной существующей бронью.
Пользователь бронирует проектор с 12:00 до 14:30 по тарифу 250 рублей в час.
Предыдущая бронь заканчивается в 12:00, поэтому новая подтверждается.
Стоимость — 750 рублей. Данные заданы в программе, сохранения пока нет.

### План развития проекта

#### Этап 1: Консольная версия

- Проверка доступности и расчёт стоимости бронирования.
- Добавление списка оборудования и бронирований.
- Ввод данных, консольное меню и работа с файлами.
- Создание классов User, Equipment, Booking и Period.

#### Этап 2: Веб-приложение

- Настройка проекта на Django.
- Подключение базы данных и создание моделей.
- Регистрация и авторизация пользователей.
- Каталог оборудования и страницы бронирований.
- Создание, просмотр, изменение и отмена бронирований.
- Админка для управления оборудованием.

#### Этап 3: Расширение функционала

- Поиск оборудования и фильтрация по доступности.
- Личный кабинет с историей бронирований.
- Разграничение прав пользователей и администраторов.
- Тестирование основных сценариев и исправление ошибок.

#### Этап 4: API и развёртывание

- Разработка REST API.
- Контейнеризация приложения в Docker.
- Настройка CI/CD.

## Запуск проекта

Нужен Python 3.10 или новее. Дополнительные библиотеки не требуются.
Команды выполняются из папки проекта в PowerShell.

### 1. Создание виртуального окружения

```powershell
py -3 -m venv .venv
```

Если команды `py` нет, вместо неё нужно указать путь к `python.exe`.

### 2. Запуск программы

```powershell
.\.venv\Scripts\python.exe main.py
```

### 3. Запуск тестов

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```
