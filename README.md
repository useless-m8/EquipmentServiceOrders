# Сервис бронирования оборудования

Сквозной проект по Python. Сейчас сделана первая практическая работа.

## Назначение

Сервис для бронирования техники на определённое время. Можно проверить,
свободно ли оборудование, и посчитать стоимость бронирования.

## Целевая аудитория

Студенты, сотрудники и другие пользователи, которым нужна техника во
временное пользование. Администратор будет управлять оборудованием и бронями.

## Предметная область

Пользователь выбирает оборудование и период. Если техника исправна и на
это время нет другой брони, бронирование можно подтвердить.

## Основные сущности

- Пользователь: имя, email, активность, роль.
- Оборудование: название, описание, исправность, тариф.
- Бронирование: пользователь, оборудование, период, статус, стоимость.
- Период: дата и время начала и окончания.

У пользователя может быть несколько бронирований. Одно оборудование можно
бронировать на разные периоды. Каждая бронь относится к одному пользователю
и одному устройству.

## Основные функции

В ПР1 реализованы:

- проверка периода: окончание должно быть позже начала;
- проверка доступности оборудования и пересечения с другой бронью;
- расчёт стоимости по часовому тарифу;
- подтверждение брони или отказ, если пользователь неактивен или техника недоступна.

В `main.py` задан пример с проектором: бронь с 12:00 до 14:30 при тарифе
250 рублей в час. Каждый начатый час оплачивается полностью, поэтому
стоимость получается 750 рублей.

Предыдущая бронь заканчивается в 12:00. Новая может начинаться в это же
время: такие периоды не пересекаются.

Пока программа работает с заданными данными и одной существующей бронью.
Ввода и сохранения данных ещё нет.

## Запуск

Python 3.10 или новее, дополнительные библиотеки не нужны.

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe main.py
```

Если команды `py` нет, вместо неё нужно указать путь к `python.exe`.

Проверка тестов:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

- ПР10–11: формы, регистрация, вход и права доступа.
- ПР13–15: тестирование и исправление ошибок.
- Дальше: REST API, Docker и CI/CD.
