# EquipmentServiceOrders
## Сервис бронирования оборудования

### Целевая аудитория

- Студенты: для бронирования техники на занятия и проекты.
- Сотрудники: для резерва оборудования на работу и мероприятия.
- Администраторы: для управления техникой и бронированиями.

### Описание предметной области

Пользователь выбирает оборудование и время. Бронь создаётся, если
пользователь активен, техника исправна и время свободно.
Отменённые бронирования остаются в истории и не занимают оборудование.

### Основные классы

| Класс | Данные | Что делает |
| --- | --- | --- |
| User | имя, email, активность | Хранит данные пользователя |
| Equipment | название, тариф, исправность | Считает стоимость |
| Period | начало и конец | Проверяет период и его пересечение с другой бронью |
| Booking | пользователь, техника, период, статус | Хранит бронь, её стоимость и отмену |

Бронь связана с объектами пользователя, оборудования и периода.
В JSON для этих связей сохраняются ID.

### Основные функции

- Просмотр и поиск оборудования.
- Проверка доступности на выбранный период.
- Расчёт стоимости по тарифу.
- Создание и отмена брони в консольной версии.
- Просмотр оборудования и броней в браузере.
- Загрузка и сохранение данных в JSON.

Каждый начатый час оплачивается полностью. Бронь на 2,5 часа по тарифу
250 рублей в час стоит 750 рублей. Тариф сохраняется в брони, поэтому
изменение цены оборудования не меняет цену уже созданного бронирования.

### Веб-страницы

| Адрес | Содержание |
| --- | --- |
| `/` | Главная страница и ссылки на разделы |
| `/equipment/` | Список оборудования |
| `/equipment/1/` | Карточка оборудования и проверка периода |
| `/bookings/` | Список бронирований |
| `/bookings/1/` | Карточка бронирования и связанные объекты |
| Другой адрес | Страница 404 при выключенном режиме отладки |

Сайт читает объекты ПР3 из JSON. Можно проверить свободный период на
странице оборудования, для этого через форму отправляется GET-запрос.
Создание брони через браузер появится в следующих работах.

### Как устроен проект

- `main.py` — консольное меню.
- `manage.py`, `config/` — запуск и настройки Django.
- `homepage/` — главная страница и стили сайта.
- `templates/` — HTML-шаблоны страниц и общий `base.html`.
- `equipment/` — страницы оборудования.
- `bookings/` — страницы бронирований.
- `core/models/` — классы пользователя, оборудования, периода и брони.
- `core/services.py` — поиск, сортировка и проверка доступности.
- `core/storage.py` — загрузка и сохранение JSON.
- `core/utils.py` — ввод данных в консольном меню.
- `tests/` — тесты консольной версии, `equipment/tests.py` — тесты сайта.

### План развития

#### Этап 1: Консольная версия

- Классы, меню, отмена брони, JSON и проверки — сделано.

#### Этап 2: Веб-приложение

- Django-проект, главная, страницы оборудования и бронирований — сделано.
- Django URL, Bootstrap, просмотр данных из JSON — сделано.
- Django ORM и база данных PostgreSQL.
- Регистрация, формы и создание брони через сайт.
- Перенос страниц на Django-шаблоны — сделано.

#### Этап 3: Дальше

- Личный кабинет и права пользователей.
- REST API.
- Docker и CI/CD.

## Запуск

Нужен Python 3.10 или новее. Команды для PowerShell из папки проекта.

### 1. Окружение и зависимости

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

### 2. Запуск PostgreSQL

Установи Docker Desktop и запусти его. В отдельном PowerShell из папки
проекта подними базу:

```powershell
docker compose up -d db
```

Затем создай служебные таблицы Django и запусти сайт:

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver
```

По умолчанию подключение идёт к `127.0.0.1:5433`. Порт 5433 выбран, чтобы не мешать установленному PostgreSQL. Параметры задаются
переменными `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`,
`POSTGRES_HOST` и `POSTGRES_PORT`. Для локального запуска можно скопировать
`.env.example` в `.env`. Для локальной разработки заданы простые пароли;
не используй их на сервере в интернете.

PostgreSQL пока хранит служебные таблицы Django. Оборудование и бронирования
веб-версия пока читает из JSON; перенос этих сущностей в Django ORM будет
следующим этапом.

Чтобы временно использовать локальную SQLite вместо PostgreSQL:

```powershell
$env:DATABASE_ENGINE = "django.db.backends.sqlite3"
```

### 3. Запуск сайта

Открыть [http://127.0.0.1:8000/](http://127.0.0.1:8000/).
Сначала сайт читает `data/service.json`, если он существует,
иначе — `data/example.json`.

### 4. Консольная версия

```powershell
.\.venv\Scripts\python.exe main.py
```

Для проверки примера без меню:

```powershell
.\.venv\Scripts\python.exe main.py --demo
```

### 5. Проверки

```powershell
.\.venv\Scripts\python.exe manage.py check
.\.venv\Scripts\python.exe manage.py test equipment
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m flake8 .
```
