# EquipmentServiceOrders
## Сервис бронирования оборудования

### Целевая аудитория

- Студенты: для бронирования техники на занятия и проекты.
- Сотрудники: для резервирования оборудования на работу и мероприятия.
- Администраторы: для управления техникой и контроля бронирований.

### Описание предметной области

Пользователь выбирает оборудование и период использования. Бронь можно
создать, если пользователь активен, техника исправна и время свободно.
Одна бронь может начинаться сразу после окончания другой.
Отменённые бронирования остаются в истории и не занимают оборудование.

### Основные классы

| Класс | Атрибуты | Методы и свойства |
| --- | --- | --- |
| User | id, name, email, is_active | __init__, __str__ |
| Equipment | id, name, hourly_rate, is_working | calculate_cost, __init__, __str__ |
| Period | start, end | overlaps, billable_hours, __init__, __str__ |
| Booking | id, user, equipment, period, hourly_rate | cancel, status, cost, is_cancelled, __init__, __str__ |

`Booking` хранит ссылки на объекты `User`, `Equipment` и `Period`.
Например, название техники доступно через `booking.equipment.name`.
В списках программы хранятся объекты этих классов.

Период проверяет время и пересечения, оборудование считает цену,
бронирование хранит своё состояние и отменяется через `cancel()`.
Для состояния отмены и границ периода используются свойства `@property`.
Связь между классами сделана через композицию: бронь содержит другие объекты.
Наследование здесь пока не требуется.

### Основные функции

- Просмотр оборудования с сортировкой по цене.
- Поиск по названию и добавление оборудования.
- Просмотр и добавление пользователей.
- Проверка доступности и расчёт стоимости.
- Создание, просмотр и отмена бронирований.
- Подбор свободной техники на выбранный период.
- Загрузка и сохранение данных в JSON.

Каждый начатый час оплачивается полностью. Например, бронь проектора
с 12:00 до 14:30 при тарифе 250 рублей в час стоит 750 рублей.
Тариф сохраняется в брони, поэтому изменение цены оборудования не меняет
стоимость уже созданных бронирований.

### Что изменилось в ПР3

Раньше в программе был один пример с переменными и отдельными функциями.
Теперь сущности представлены классами, добавлены списки объектов, меню и JSON.
Версии ПР2 в репозитории не было, поэтому меню и хранение добавлены на этом этапе.

Проверка периода перенесена в `Period`, расчёт стоимости — в `Equipment`.
Статус и отмена относятся к `Booking`. Поиск, сортировка и проверка
доступности остались функциями в `services.py`, так как работают со списками.
Загрузка и сохранение находятся отдельно в `storage.py`.

### Хранение данных

При первом запуске загружается пример из `data/example.json`.
После добавления или отмены данные сохраняются в `data/service.json`.
При следующем запуске используется этот файл. Он исключён из Git.

В JSON бронирование хранит `user_id` и `equipment_id`. При загрузке по ним
находятся объекты пользователя и оборудования. Даты хранятся строками,
тарифы — строками для точного преобразования в `Decimal`.

Если файл повреждён, программа сообщает об ошибке и не перезаписывает его.

### План развития проекта

#### Этап 1: Консольная версия

- Классы, меню, проверка доступности и расчёт стоимости — сделано.

- Настройка проекта на Django и подключение базы данных.
- Регистрация и авторизация пользователей.
- Каталог оборудования и страницы бронирований.
- Формы создания, изменения и отмены брони.
- Админка для управления оборудованием.

#### Этап 3: Расширение функционала

- Личный кабинет с историей бронирований.
- Разграничение прав пользователей и администраторов.
- Расширение тестов для веб-приложения.

#### Этап 4: API и развёртывание

- REST API.
- Docker.

## Запуск проекта

Нужен Python 3.10 или новее. Команды для PowerShell из папки проекта.
Программа использует стандартную библиотеку, зависимости нужны для проверок.

### 1. Создание окружения и установка зависимостей

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если команды `py` нет, вместо неё нужно указать путь к `python.exe`.

### 2. Запуск программы

```powershell
.\.venv\Scripts\python.exe main.py
```

Откроется меню. Для периода используется формат `2026-10-15 12:00`.
Время местное, без часового пояса. Проверки относительно сегодняшней даты нет:
можно использовать фиксированные даты для демонстрации.

Пример из ПР1 без ввода и сохранения данных:

```powershell
.\.venv\Scripts\python.exe main.py --demo
```

Другой файл для хранения:

```powershell
.\.venv\Scripts\python.exe main.py --data data/my_bookings.json
```

### 3. Запуск тестов

```powershell
.\.venv\Scripts\python.exe -m pytest -v
```

Тесты проверяют объекты, стоимость, пересечения периодов, отмену,
сохранение и загрузку, ошибки данных и работу меню.

### 4. Проверка кода

```powershell
.\.venv\Scripts\python.exe -m flake8 .
```
